# Batch 35 — opt-in dynamic sample-peak limiter

Existing original speech master and all prior recipes are unchanged by default. New `project-mix-compose --limiter-ceiling 16000` option (with usual project ID and audio rights acknowledgment) and dashboard Mix control apply a deterministic integer gain ceiling to the entire separate mix, including intro/outro and music. Zero disables; valid nonzero values are integers 8000–28000. Gain attacks immediately and returns toward unity by 1250 parts per million per sample (at most 800 frames / 50 ms); state carries across block boundaries. No extra dependencies, network, overwrite or approval inheritance.

The limiter recipe is stored in the mix receipt and regenerated by exact PCM audit. Existing receipts with no limiter remain compatible. A limiter cannot be combined with static loudness-target normalization, because subsequent gain could violate the selected sample ceiling. True-peak measurement is available separately in audio diagnostics, but this algorithm does not guarantee intersample or encoded AAC true peak, perceived quality or a LUFS target. No real listening or actual device acceptance.

63 authored regression cases: 42 sample/ceiling combinations, 12 invalid settings, 3 release checks, 1 block/bypass test, 3 project/dashboard audit checks, 1 incompatible target check, 1 CLI/browser markup check. The first 58 passed in a standalone local Python harness with the same limiter source and equivalent test bodies; full checkout unavailable because this execution environment could not resolve github.com. Five integration cases and full repository CI not run locally. Existing stable V3 untouched.
