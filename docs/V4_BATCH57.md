# Batch 57 — private render performance history

Records the last 30 successfully audited new non-fixture renders per project in private render-performance.json. Variants: neural-studio, mixed-video, mixed-studio; group totals by variant, landscape/vertical/square, and resume mode. Counts rendered and restored units/frames separately. Monotonic elapsed milliseconds include unit preparation, render or restore, verification and cache save as applicable. Overall elapsed covers work after initial source context preparation through final audit, not all episode creation or initial input audit. No model inference timing, no precise ETA, no failed/stopped attempt history and no repeat entry for existing-candidate inspection. No dialogue, source paths, secrets or network transfer. Default enabled for newly audited non-fixture exports; oldest history records trimmed to 30, never video/cache files. History is auxiliary, not a candidate receipt or authenticated benchmark. Existing malformed/symlinked or oversized history is refused; write failure logged without invalidating successful media. Inspection under project lock: CLI `project-render-performance --project-id ID`, dashboard "Inspect render performance history".

Existing cache identity includes renderer source hashes, so updating neural and mixed render modules causes old cache namespaces to be bypassed. Old cache files are retained and can be cleaned with explicit Batch 53/56 tools. No automated migration. Existing receipts and output contents unchanged by timing instrumentation.

Actual isolated pytest: 46 passed in 0.17 seconds (18 round-trip combinations, 11 invalid records, 6 corrupt history cases, 6 state validation, 5 individual retention/grouping/empty/symlink/failure cases). Two repository route/lock cases authored but unexecuted; total 48 dedicated cases. Full project integration and actual long-episode performance not verified; no new dependencies.
