# V4 graphical character, source and local model configuration

Open the private localhost dashboard. Character library controls list and load profiles, create a new profile (blank ID) or immutable revision (existing parent ID), and attach an authorized PNG to create another version. The returned ID identifies the new record. Load cast choices for the selected project, choose a distinct character for each presenter and explicitly assign once. Existing project casts and old character records stay unchanged. This does not create an AI image or verify identity/voice quality.

Source import accepts browser-selected trusted PDF/DOCX/TXT/MD matching the project's declared input kind; up to 8 MB, 30 PDF pages and 12,000 extracted characters. No OCR or arbitrary local path reads for source files. The server stages bytes under a unique private temporary directory with a fixed source filename (evidence locator is source.ext), then calls the existing immutable importer. Portraits use the existing 12 MB PNG checks and rights declaration. Temporary inputs are removed on ordinary completion or failure; abrupt shutdown may leave private scratch. URL capture separately requires explicit internet retrieval consent, uses existing public HTTPS pinned-DNS/TLS checks, and does not capture a research pack or call AI. DOCX XML is now restricted to UTF-8 with DTD/entity rejection, including rejection of UTF-16.

Model controls save existing Kokoro, SadTalker or eSpeak paths; specify absolute paths, no explicit UNC/device paths. Mapped/network-mounted volumes are not independently detected. Saving Kokoro paths hashes the selected assets, so large files may take time. The existing model configuration validator checks paths and optional replacement; no executables launched, dependencies installed, weights downloaded or real inference certified. Use trusted local paths only.

Every write requires a fresh authoring checkbox; portrait and URL actions additionally require specific rights/network consent. Existing localhost host/origin, CSRF and action mutex protections apply. No arbitrary commands, paths for source upload, or HTTP media-serving routes. File bytes go to the local app only, not an external service. API keys, research pack capture, model inference and recorded human approvals remain CLI-only. Tests exercise authoring adapters, validation, and markup; actual browser/device acceptance remains pending.
