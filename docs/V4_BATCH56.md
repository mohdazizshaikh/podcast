# Batch 56 — budget-based render cache retention

New explicit preview and apply operations for all existing private render cache types. CLI preview: `project-studio-cache-prune-plan --project-id ID --max-mib 2048 --keep-newest 1`. Add repeatable `--protect KEY` for named namespaces. Apply with `project-studio-cache-prune`, identical policy parameters, `--plan-sha256 HASH` from the preview and `--acknowledgment I_STOPPED_ALL_RENDER_PROCESSES_AND_AUTHORIZE_THIS_CACHE_PRUNE_PLAN`. Dashboard includes budget, keep count, protected keys, preview digest and separate deletion consent; standard local authoring consent is also required.

Budget is logical file MiB, 0–1,048,576; newest count 0–128, defaults to one. Protect explicitly named existing namespaces and the newest N by latest file modification timestamp, with deterministic hash tie-break; empty namespaces have no file timestamp and zero-byte entries are not chosen just to meet a byte budget. Select oldest eligible positive-size namespaces until under budget or no eligible space remains. The preview is read-only and returns initial/planned-deleted/remaining logical bytes, protected keys, each proposed namespace snapshot, budget_met and a plan SHA-256 binding the policy and entire inventory. The apply operation recomputes the full plan under the project lock and refuses any change. Each selected namespace is deleted using the existing narrow, snapshot-checked cleanup API. Protected entries are never selected even when the budget cannot be met. No automatic background pruning or default retention change. File modification time is not last access time or proof that media is obsolete. Zero budget plus keep=0 and no protected keys can select all positive-size caches; preview and explicit consent are mandatory. Partial deletion on filesystem failure remains possible; inspect again. No user cache was deleted in development.

Verification: actual local pytest 68 passed in 0.44 s with the previously verified cache/admin modules (32 real filesystem plan/apply combinations, 9 under-budget cases, 6 each invalid budget/keep/protected, 6 stale/consent/policy cases, 3 individual boundary cases). First run exposed a negative slice bug when retention count exceeded inventory size, now corrected and rerun. Four additional full-repository CLI/dashboard/lock cases authored but not run. Total 72 cases. Full CI, Windows and actual long-episode acceptance remain unverified. No new dependencies.
