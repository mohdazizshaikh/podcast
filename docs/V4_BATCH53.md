# Batch 53 — explicit render cache inventory and cleanup

Adds `project-studio-cache-inventory --project-id ID` and `project-studio-cache-delete --project-id ID --namespace KEY --snapshot-sha256 SNAPSHOT --acknowledgment I_STOPPED_ALL_RENDER_PROCESSES_AND_AUTHORIZE_DELETING_THIS_CACHE_NAMESPACE`. Dashboard authoring panel supports the same operations; deletion requires both the standard local authoring consent and a separate stopped-process/deletion checkbox. Inspect and remove take the existing project lock; never remove stale locks automatically.

Inventory lists up to 128 namespaces and 100,000 entries in total; each namespace reports logical file bytes, entry count, complete file-pair count, incomplete count, newest file mtime in nanoseconds and metadata snapshot SHA-256. A complete pair is structural, NOT a verified media receipt. Inventory does not read video contents, infer whether a namespace is current or obsolete, or estimate physical disk space recovered. Deletion requires a valid lowercase 64-character namespace and its matching latest metadata snapshot. It permits removal of structurally incomplete entries containing only known files. It rejects unsafe symlinks/reparse points, wrong path types, unrecognized entry names/files and changed metadata; all target entries are inventoried before any unlink. Deletes only the selected namespace's known files and directories, no recursive arbitrary tree deletion, no original or final candidate edits. No automatic pruning. Partial deletion is possible on filesystem failure; refresh inventory and retry explicitly. Metadata checks and application locking are not protection against malicious concurrent local writers. Cache management remains local and no user's actual private cache was deleted in development.

Actual isolated pytest run: 61 passed in 0.45 s (24 inventory/deletion combinations, 5 stale snapshot cases, 14 invalid input cases, 4 acknowledgment, 5 symlink, 4 unexpected entry, 3 entry bounds, 1 namespace bound, 1 missing-cache case). Three additional repository integration cases authored: CLI/dashboard forwarding and two project-lock operations; unexecuted. Total 64 dedicated cases. Full CI and physical Windows acceptance remain unverified. Existing manual cleanup guidance in Batch 52 is superseded by these explicit tools; automatic retention/pruning remains pending.
